# Модель для предсказания вероятности задержки
Выполнила: Тулянцева Альбина

Дата выполнения: 24.07.2026

**Описание проекта**: CargaPronto - это крупнейший логистический оператор, связывающий производственные хабы Пуэрто-Рико с потребителями в США. Недавно внутренний аудит выявил критическую ситуацию в компании: 55% всех заказов доставляются с задержкой. Сумма выплаченных штрафов из-за нарушения SLA (соглашение об уровне обслуживания) за прошлый квартал превысила бюджет на развитие IT-инфраструктуры. Крупнейшие ритейлеры США уже выставили ультиматум: либо CargaPronto стабилизирует сроки, либо контракты будут расторгнуты. Внутри компании нет единого мнения о причинах кризиса.

Отдел клиентского сервиса, который ежедневно занимается антикризисной коммуникацией и обработкой претензий, выдвинул гипотезу: если CargaPronto научится заранее предсказывать риск задержки, то компания сможет точечно менять приоритеты доставки. Это позволит снизить общую сумму штрафов за счёт предотвращения опозданий в самых критичных сегментах.

**Цель**: создать модель, которая будет заранее предсказывать риск задержки доставки.

**Задачи**:

1. Загрузить данные
2. Провести исследовательский анализ данных
3. Разделить данные на выборки
4. Обучить базовую модель
5. Провести кластеризацию принаков
6. Выявить лучшую модель
7. Составить выводы и рекомендации

**Данные**:

Датасет уникальных клиентов:

customer_id — уникальный номер клиента в системе ERP. Служит ключом для связи с таблицей заказов.

customer_lat — широта местонахождения клиента.

customer_lon — долгота местонахождения клиента.

recency — количество дней, прошедших с момента последнего заказа до точки отсчёта. Соответствует показателю Recency.

total_orders — общее количество совершённых заказов. Соответствует показателю Frequency.

total_sales — суммарная выручка, которую клиент принёс компании за всё время. Соответствует показателю Monetary.

recency — количество дней, прошедших с момента последнего заказа до точки отсчёта. Соответствует показателю Recency.

total_orders — общее количество совершённых заказов. Соответствует показателю Frequency.

total_sales — суммарная выручка, которую клиент принёс компании за всё время. Соответствует показателю Monetary.

Датасет заказов:

order_id — уникальный номер заказа.

customer_id — идентификатор клиента. Служит ключом для связи с профилем из первой таблицы.

order_date — дата и время совершения покупки.

category_name — категория заказанного товара.

item_price — стоимость товара в заказе.

shipping_mode — выбранный режим доставки ( Standard Class, First Class, Second Class, Same Day.

late_delivery_risk — результат доставки, целевая переменная:

1 — заказ доставлен с задержкой;
0 — заказ доставлен вовремя.

**Постановка задачи машинного обучения**: данная работа включает в себя решение задачи бинарной классификации. Базовой моделью выбрана Логистическая регрессия. Основная модель — градиентный бустинг CatBoost для выявления нелинейных зависимостей. Целевая метрика — ROC-AUC, поскольку она фокусируется на способности модели корректно упорядочивать объекты по риску, что напрямую соответствует операционной логике диспетчеров. Порог успеха установлен на уровне ROC-AUC > 0.75. Входные данные требуют предварительной проверки на пропуски, дубликаты и целостность связей между клиентами и заказами, а также EDA, включающий баланс классов, визуализацию геолокации покупателей с отсечением аномалий и корреляционный анализ.

Обучение выполняется с разделением выборки через GroupShuffleSplit, чтобы избежать утечки данных между заказами одного клиента. Базовая модель строится исключительно на сырых признаках заказа без дополнительной обработки, что даёт точку отсчёта. Затем вводятся два типа кластерных признаков: географические зоны (KMeans++ на координатах клиентов, с выбором числа кластеров методом локтя) и поведенческие сегменты на основе RFM-показателей (Recency, Frequency, Monetary), возвращаемости (Return Rate) и средней скидки (Average Discount), с визуализацией качества кластеризации через t-SNE. Эти синтезированные признаки добавляются в обе модели, после чего сравнивается прирост ROC-AUC. Финальная лучшая модель подлежит углублённому тестированию: строится матрица ошибок, анализируется важность признаков (в том числе вклад новых кластерных переменных) и формулируются бизнес-рекомендации. Основной критерий приемки — превышение ROC-AUC = 0.75, при этом приоритет отдаётся CatBoost, если он показывает устойчивое превосходство над логистической регрессией, а вклад кластерных признаков должен быть интерпретирован с точки зрения операционных действий для разных групп клиентов и логистических зон.
